# Скрипт для препроцессинга комбинаций тестирования

## Сценарий использования

solution.py принимает путь до файла в качестве аргумента и выводит результат в stdout.

Файл описывает тестовые конфигурации в компактном виде. Скрипт раскрывает компактное представление в плоский вид.

Тестовая конфигурация описывается набором параметров, для которых определены свойства.
Свойства относятся к параметру и отделены от параметра символом '@'.
Несколько свойств могут быть одновременно описаны для одного параметра, они указываются через запятую.
У параметра может не быть свойств. При этом на конце остаётся '@'.
Пример конфигурации:
```
LLM@gpt,params=79B tokens@percent=10,cached,internal
```
Здесь 2 параметра: LLM, tokens
У параметра LLM определены 2 свойства: gpt, params=79B
У параметра tokens определены 3 свойства: percent=10, cached, internal

Компактное описание позводяет описывать только различающиейся части с помощью оператора `[...]`, например для описания
```
llm@glm test@bugbounty,lvl=medium token@yes,limit=200000
llm@glm test@bugbounty,lvl=medium token@yes,limit=500000
```
мы можем записать
```
llm@glm test@bugbounty,lvl=medium token@yes [token@limit=500000 token@limit=200000]
```
как видно в примере, общие свойство `yes` для параметра `token` вынесено в общую часть.

в случае, если различающиеся части состоят из нескольких параметров, параметры могут быть сгруппированы с помощью оператора `{...}`.
Например для описания
```
llm@glm test@bugbounty,lvl=high token@yes,limit=200000
llm@glm test@bugbounty,lvl=medium token@no,limit=500000
```
мы можем использовать
```
llm@glm test@bugbounty token@yes,limit=200000 \
[ {test@lvl=high test@lvl=medium} {token@yes,limit=200000, token@no,limit=500000}]
```
## Логика скрипта

Скрипт зачитывает конфигурации поштучно.
Скрипт проверяет правильность вложенных скобочных подпоследовтельностей "[...]" и "{...}"

В поддерживает 2 множества конфигураций:
  `compact`: конфигурации, которые находятся в работе
  `flat`: конфигурации, в которых раскрыты все скобки
Изначально все конфигурации попадают во множество `compact`.
Скрипт достаёт конфигурацию из множества `compact` и пытается применить к ней опреацию раскрытия скобок. В результате может получиться одна или несколько новых конфигурцаций. Скрипт складывает получившеся конфигурации обратно во множество `compact`.
Если операцию раскрытия применить невозомжно, значит данная конфигурация полностью обработана и может быть перемещена в итоговое множество `flat`.

Когда первое множество становится пусто скрипт переходит ко второй части.
Нужно добиться уникальности параметров в описании, т.е. объединить все свойства одного и того же параметра через ','. Например из
```
test@bugbounty test@lvl=medium x@
```
сделать
```
test@bugbounty,lvl=medium x@
```
После этого строки сортируются и отправляются на печать.

### Операция раскрытия
Операция работает с кофнигурацией. Сначала находит наиболее вложенную пару соответствующих друг другу в разбиении на правильную скобочную последовательность "[...]". Раскрыть "[...]" значит сделать из текущий конфигурцации серию независимых конфигураций, где вместо выражения в скобках, подставляется каждый из его элементов отдельно.
Элементы разделены пробелами. Подстроки, обрамлённые парными "{...}" считаются одним элементом.
При раскрытии "[...]" все вложенные "{...}" опускаются.
Если в строке отсутствуют "[...]", то все "{...}" могут быть опущены.

#### Важные нюансы раскрытия:
- **Порядок слияния свойств**: при слиянии одинаковых параметров свойства сохраняются в том порядке, в котором они появляются в конфигурации после раскрытия скобок
- **Пример**: `test@review token@per_line=10 [token@rag token@full]` → `test@review token@rag,per_line=10` и `test@review token@per_line=10,full` (порядок свойств соответствует порядку появления в раскрытой конфигурации)
- **Уникальность конфигураций**: дубликаты конфигураций должны сохраняться, если они происходят из разных входных конфигураций, но удаляются при слиянии свойств в одной конфигурации
- **Уникальность параметров**: идентичные параметры в рамках одной конфигурацию объядиняются, при это их свойства считаются уникальными и конкатенируются через `,`.
- **Обработка пустых свойств**: параметр с пустыми свойствами (например `param@`) является валидным и должен обрабатываться


## Структура входного файла
- может содержать пустые строки
- может содержать комментарии, начинающиейся с '#'
- несколько линии могут быть объединены с помощью '\' в конце строки
- файл описыват конфигурации
- каждая конфигурация полностью независима
- конфигурация - последовательность строк, объединённых '\'
Пример
```
# Test 1. comments and line breakes
# Subtest. Line break via \\ symbol

scenario@stream,size=512 \
timer@high
```

# Примеры

### Простое группирование свойств
```
# Вход:
{llm@gpt llm@glm}

# Выход:
llm@gpt,glm
```

### Простое раскрытие скобок
```
# Вход:
[llm@gpt llm@glm]

# Выход:
llm@gpt
llm@glm
```

### Сложный пример с вложенными структурами
```
# Вход:
[llm@gpt llm@glm]                                           \
[                                                           \
    { test@bugbounty                                        \
        [{test@lvl=easy token@limit=200000}                 \
         {test@lvl=hard token@limit=500000}]                \
    }                                                       \
    { test@review token@per_line=10                         \
        [ token@rag token@full]                             \
    }                                                       \
]

# Выход:
llm@glm test@bugbounty,lvl=easy token@limit=200000
llm@glm test@bugbounty,lvl=hard token@limit=500000
llm@glm test@review             token@rag,per_line=10
llm@glm test@review             token@full,per_line=10
llm@gpt test@bugbounty,lvl=easy token@limit=200000
llm@gpt test@bugbounty,lvl=hard token@limit=500000
llm@gpt test@review             token@rag,per_line=10
llm@gpt test@review             token@full,per_line=10
```

## Технические детали и краевые случаи

### Парсинг файла
- **Разделение конфигураций**: каждая конфигурация завершается переносом строки, который не заканчивается на '\' (обратный слэш). Пустые строки и комментарии игнорируются.
- **Обработка пробелов**: лишние пробелы в начале/конце строк игнорируются, множественные пробелы внутри конфигураций нормализуются.

### Алгоритм раскрытия скобок
1. **Рекурсивный подход**: обработка начинается с наиболее вложенных скобок `[...]`
2. **Глубина вложенности**: при наличии нескольких уровней вложенности раскрываются сначала внутренние
3. **Сохранение порядка**: порядок элементов в скобках сохраняется в результирующих конфигурациях

### Слияние параметров
- **Дедупликация**: свойства считаются уникальными и никак не конфликтуют, например допустимы `test@lvl=easy,lvl=hard`
- **Приоритет свойств**: свойства из скобочных расширений имеют приоритет при сохранении порядка
- **Специальные случаи**: 
  - Пустые параметры (`param@`) сохраняются в результирующей конфигурации

### Обработка дубликатов
- **Межконфигурационные дубликаты**: если одинаковые конфигурации получаются из разных входных конфигураций, они сохраняются
- **Внутриконфигурационные дубликаты**: при слиянии свойств одного параметра дубликаты удаляются

### Сложные примеры
```
# Несколько скобочных expansions
# Вход:
a@a_common [{a@a b@b} {a@A b@B}]

# Выход:
a@a_common,a b@b
a@a_common,A b@B

# Вложенные скобки
# Вход:
[{test@lvl=easy token@limit=200000} {test@lvl=hard token@limit=500000}]

# Выход:
test@lvl=easy token@limit=200000
test@lvl=hard token@limit=500000

# Слияние дублирующихся параметров
# Вход:
test@bugbounty test@lvl=medium x@

# Выход:
test@bugbounty,lvl=medium x@
```

## Распространённые ошибки реализации

### 1. Неправильное определение границ конфигураций
```
# Ошибка: обработка всего файла как одной конфигурации
# Правильно: каждая конфигурация завершается переносом строки, который не заканчивается на '\'

# Вход:
a@a
b@b c@c

# Правильная обработка:
# Конфигурация 1: a@a
# Конфигурация 2: b@b c@c
```

### 2. Некорректный порядок слияния свойств
```
# Ошибка: попытка искусственно изменить порядок свойств вместо сохранения исходного
# Правильно: свойства сохраняются в том порядке, в котором они появляются в раскрытой конфигурации

# Вход:
test@review token@per_line=10 [token@rag token@full]

# Правильный выход:
test@review token@per_line=10,rag
test@review token@per_line=10,full
# Порядок соответствует порядку появления в конфигурации после раскрытия скобок
```

### 3. Потеря дубликатов конфигураций
**Ошибка**: использование множества (set) на финальном этапе, что удаляет легитимные дубликаты
**Правильно**: дубликаты сохраняются, если они происходят из разных входных конфигураций

### 4. Неправильная обработка вложенных скобок
**Ошибка**: раскрытие скобок снаружи внутрь вместо изнутри наружу
**Правильно**: сначала раскрываются наиболее вложенные скобки

### 5. Игнорирование пустых свойств
**Ошибка**: отбрасывание параметров с пустыми свойствами (`param@`)
**Правильно**: такие параметры являются валидными и должны сохраняться

### 6. Некорректная токенизация
**Ошибка**: неправильное разделение на токены при наличии пробелов внутри скобок
**Правильно**: `{...}` рассматривается как единый токен при извлечении элементов из `[...]`

### 7. Проблемы с обработкой продолжений строк
**Ошибка**: неправильная обработка '\' в конце строк
**Правильно**: '\' соединяет строки, но пустые строки и комментарии всё равно разделяют конфигурации

### 8. Неправильное определение наиболее вложенных скобок
**Ошибка**: выбор первых найденных скобок вместо наиболее вложенных
**Правильно**: используется подсчёт глубины вложенности для определения правильного порядка

## Сравнение результатов в тестах

Для проверки корректности реализации используется нормализация конфигураций перед сравнением:

1. **Сортировка параметров**: все параметры в конфигурации сортируются по имени
2. **Сортировка свойств**: все свойства в рамках одного параметра сортируются по алфавиту
3. **Удаление дубликатов**: дублирующиеся свойства удаляются
4. **Покомпонентное сравнение**: нормализованные конфигурации сравниваются как отсортированные строки

Это позволяет игнорировать порядок следования параметров и свойств при сравнении, фокусируясь на семантической правильности раскрытия конфигураций.
